# CLAUDE.md — Root Access

Guidance for Claude Code sessions in this repository. Read this first, then `RUBRIC.md` (what is graded and where it
lives) and `ROADMAP.md` (what was built, stage by stage). `RELEASE_REPORT.md` describes the delivered state (`v1.0`);
the player-facing documentation is `Documentatie/DOCUMENTATIE.md`.

## Project

Graded university project: **Root Access**, a 2D side-scrolling cyberpunk stealth-platformer in **Unity 6000.3.29f1
(6.3 LTS)**, URP 2D, C#. The player is a hacker: platforming, stealth, hacking minigames, drones with our own A*.
Target: ≥30 min of gameplay (Hub + 5 levels), all 12 rubric items + bonuses, Windows x64 build and project on Google Drive.
UI language is **Romanian**; every player-facing string lives in `Scripts/Core/Strings.cs`.
The developer is an experienced full-stack dev who is new to Unity: explain Unity-specific decisions in docs, not chat.

## Hard rules

- **Never hand-write Unity YAML** (`.unity .prefab .asset .controller .anim .mat .mixer .meta`). Change the generator
  instead (`Scripts/Editor/SceneBuilder.cs`, `Editor/Generation/*Factory.cs`, `PlaceholderArtGenerator.cs`,
  `Editor/Generation/Art/*.cs` for the painted pixel art) and rerun it.
  Hand-written C#, `.asmdef`, `.inputactions`, `manifest.json`, `.shader/.hlsl`, docs and scripts are fine.
- **Batchmode only, project closed in the Editor.** Scripts refuse to run when `RootAccess/Temp/UnityLockfile` is locked.
  After every run read the log for `error CS`, `Exception`, `Compilation failed`, `[RootAccess][FAIL]`.
- Unity 6 APIs: `Rigidbody2D.linearVelocity`, `FindFirstObjectByType/FindObjectsByType`, new Input System only.
- Code style: C# 9+, `[SerializeField] private` fields, no public mutable fields (exception: JSON DTOs such as `SaveData`,
  `GameSettings`, `SaveEnvelope`), no magic strings (`Constants.cs`, `Ids.cs`, `Strings.cs`), guard clauses with clear
  `[ClassName]` log messages, no `Find*` in gameplay code (use `EventBus<T>`, `ServiceLocator`, serialized refs).
  XML docs on public APIs; inline comments only for non-obvious logic.
- Gameplay state is plain C# (`Inventory`, `TraceMeter`, `QuestLog`, `SkillTree`, `Wallet`, hacking models) with
  MonoBehaviour views, so it stays unit-testable and can be mirrored to NetworkVariables for co-op later.
- No internet downloads of assets. Placeholders are procedural; real packs are imported by the developer.
- Every phase ends green (compile, tests, build) and is committed with a conventional message. Do not push unless asked.

## Unity 6000.3 gotchas learned the hard way

- `Tilemap.SetTile(Vector3Int, TileBase)` does nothing in batchmode → use `SetTiles`.
- Batchmode never generates `TilemapCollider2D`/`CompositeCollider2D` geometry; `SceneBuilder.BakeTilemapColliders`
  calls `ProcessTilemapChanges()` + `GenerateGeometry()` before saving and fails the build if a solid tilemap has no paths
  (symptom otherwise: player falls through every floor, HUD shows "Viață 0/5").
- `AssetDatabase.ImportPackage` does not run in batchmode with `-quit` → pass `-importPackage` on the command line.
- Renderer2D cannot draw skyboxes or stack with UniversalRenderer: renderer index 0 = Renderer2D (gameplay),
  index 1 = UniversalRenderer (menu/credits cameras and the sky camera that renders into the gameplay backdrop quad).
- `RequireComponent` auto-adds components: add the main component before the ones that require it.
- `GetComponent<T>() ?? x` breaks on Unity's fake null → use `TryGetComponent`.
- Non-sequential enums (`Light2D.NormalMapQuality`) must be set via `intValue`, not `enumValueIndex`.
- PlayMode tests: the runner adds its own `InitTestScene…` to Build Settings — filter to `Assets/_Project/Scenes/`.
- Regenerating content rewrites sub-asset fileIDs (controllers, volume profiles): large but harmless diffs.
- Opening a new scene in batchmode can unload ScriptableObjects the build context still holds (the C# wrapper turns
  fake-null and a SerializedProperty silently stores None). Wrap SO references wired into scenes in `BuildContext.Fresh(...)`.
- Raycasts that start exactly on a collider's surface do not report it: start ground/wall probes ~0.5 above the feet.
- Sprite rigs: bones/weights go through `ISpriteBoneDataProvider` + `ISpriteMeshDataProvider` (root bone in pixels from the
  rect origin, children in parent-local pixels, vertices in rect pixels); the 2D Animation post-processor bakes bind poses.
- Netcode: create the NetworkManager on a root object (`DontDestroyOnLoad`), `EnableSceneManagement = false` when peers do
  not share scenes (the LAN Operator only runs the console); the Net asmdef needs `Unity.Networking.Transport` for
  `UnityTransport.SetConnectionData`.
- `_CameraSortingLayerTexture` needs both `m_UseCameraSortingLayersTexture` and `m_CameraSortingLayersTextureBound`
  (a sorting layer *unique id*) on the Renderer2DData; the Shader Graph property must be non-exposed.
- Shader Graphs are generated (`Editor/Generation/ShaderGraphFactory.cs` + `ShaderGraphWriter.cs`): nodes are written without
  slots (Shader Graph recreates them on load), only custom-function slots and constants are explicit. Edit the factory,
  not the `.shadergraph` files; the factory fails the build if a graph does not import as an error-free shader.

## Testing

- EditMode (`Tests/EditMode`, 120 tests): A*, Inventory, TraceMeter, SaveSystem (+migrations, GameSession round-trip),
  SkillTree, QuestLog, hacking models, EventBus, ServiceLocator, FSM, Wallet, LoreArchive.
- PlayMode (`Tests/PlayMode`, 40 tests; `LoreLogTests` check 3 distinct data logs per level; `LevelProgressionTests` redirect saves with `SessionService.UseSaveDirectory`): every project scene in Build Settings boots with no logged errors and the player
  standing on the floor; `VerticalSliceAcceptanceTests` drives the whole slice (menu → Hub → Level 1 → hack → door →
  teleport → drone chase → pause → volume → menu → Rubric Showcase); `HackingTerminalTests` solves Port Scan and
  Wire Connect through the real overlay (camera disabled, data shard + credits awarded).
- The Test Framework fails a test on any unexpected `Debug.LogError`/exception — keep logs clean, use `LogAssert.Expect`.
- Add a test with every new system; test hooks are `internal` + `InternalsVisibleTo` (see `Scripts/Hacking/AssemblyInfo.cs`).
